# 项目背景与当前实现

本项目是面向《中药学（新世纪第五版）》的证据优先 GraphRAG 实验系统。主链为：

```text
PDF/OCR → 结构化 Chunk → 受控本体抽取 → Assertion 证据层
       → Neo4j Serving 投影 → 意图路由检索 → 结构化上下文 → LLM 回答与前端可视化
```

## 一、建图与证据

`scripts/preprocess_pdf.py` 生成带页码的教材 Chunk；`scripts/build_kg_v2.py` 从 Chunk
抽取实体和事实。正式类型与谓词由 `graphragexpr/domain/ontology.yaml` 约束，未知类型
不会直接写成正式图谱标签。

每条事实先写入 `Assertion`，保存 `evidence_quote`、页码、Chunk ID、校验状态和运行版本；
只有 `ACTIVE + ACCEPTED + POSITIVE` 的事实才投影为可服务的类型化边。这样既能支持快速
查询，也能沿 `Assertion → Chunk` 回溯教材原文。Neo4j 固定使用 5.26 LTS。

## 二、检索与路由

检索主链使用原生 `neo4j` Python Driver，不依赖 `neo4j-graphrag`。`route_query()` 是
规则优先、无需 LLM 调用的路由器，根据实体链接、问题词和风险词生成 `RetrievalPlan`：

| 意图 | 检索与输出结构 |
|---|---|
| `attr` | 单味药的类型化属性卡片 |
| `reverse` | 按功效/主治反向查药表格 |
| `intersect` | 多约束硬交集及部分匹配矩阵 |
| `compare` | 多实体事实槽对齐与章节摘要 |
| `path` | 白名单关系的最多 3 跳受限路径 |
| `fallback` | 文本块全文/向量检索，作为总论问题兜底 |

`backend/api.py` 的 `/api/graphrag` 接口默认使用 `auto`，也保留 `keyword_graph`、
`vector`、`vector_cypher`、`hybrid`、`hybrid_cypher` 作为课程对照模式。返回结果包含
答案、来源、证据追踪信息和用于前端高亮的同源子图。

## 三、前端与 API

Flask 同时托管 `frontend/index.html` 和 `/api/*` 接口。问答入口是问题输入框与自动路由
选择器；原先没有实际价值的独立“搜索”卡片已从前端删除。后端 `/api/search` 仍保留为
兼容接口，供外部客户端按实体名查询，但不再由当前页面调用。

## 四、评测现状与边界

`eval/retrieval/questions.jsonl` 已冻结 120 道检索题，并完成实体、谓词、路由、拒答、
页码和 Chunk 证据的人工仲裁。当前脚本可以校验数据集并评分这些字段，但尚未实现按
排序 Chunk 计算的 `Recall@5`，也不能据此声称达到设计文档的 90% 门槛。

当前已知边界包括：总论知识不一定形成图谱关系、抽取侧主治/配伍/禁忌仍缺完整量化参照、
生成侧尚未完成 Claim–Evidence 程序化校验。详细待办见 [待办与注意事项](../待办与注意事项/)。
