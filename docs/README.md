# 技术文档

本目录收录项目的规范、设计与实现文档。阅读顺序建议自上而下。

| 文档 | 内容 | 适合谁读 |
|---|---|---|
| [项目背景说明](项目背景说明.md) | 项目由来、与老师基线仓库的关系、整体目标 | 所有人，先读这份 |
| [团队开发规范](团队开发规范.md) | 架构原则、模块边界、数据契约、Git/测试/变更管理 | 所有人，**动代码前必读** |
| [总体系统设计与可行性评审](总体系统设计与可行性评审.md) | 建图/检索/知识注入三部分的评审、统一架构、双层图模型、里程碑与职责划分 | 需要理解全局的人 |
| [KG 构建环节改进技术文档](KG构建环节改进技术文档.md) | 建图环节的问题诊断、逐条改动、实测数据、评测与阈值标定 | 建图相关开发与答辩材料 |
| [待办与注意事项](../待办与注意事项/) | 未完成项、会踩的坑、系统当前的边界 | **交接与上手前必读** |

## 冲突处理优先级

文档、Schema 与代码不一致时，按《团队开发规范》§2 的顺序处理：

```text
已批准 ADR
> 稳定数据契约与 ontology.yaml
> API/测试契约
> 当前实现
> 旧文档描述
```

发现冲突必须在 PR 中说明，不得静默绕过。
