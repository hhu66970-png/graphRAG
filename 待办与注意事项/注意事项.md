# 注意事项

按「会造成什么后果」排序。前四条会**直接损坏数据或让结论失真**。

---

## 1. `build_kg_dyn.ps1` 会清空整个数据库

`graphragexpr/extract/build_kg_dyn.py:174` 在 `CLEAR_DATABASE=true`（`.env` 默认值）时
执行 `MATCH (n) DETACH DELETE n`。

**在已有 v2 数据的库上跑它，新图会连同旧图一起被删光。**

它是改造前的旧管线，**刻意保留**作为课程报告的对照基线。正常流程不需要执行：

- 要新图 → `.\build_kg_v2.ps1` 或从数据包导入
- 真要跑旧管线做对照 → 先 `CLEAR_DATABASE=false`，或换一个库

---

## 2. 测试与生产共用数据库，隔离必须覆盖三个层面

已经因此损坏过三次数据，全部修复，但**根因仍在**（共库）。三次分别是：

| 缺陷 | 后果 | 现状 |
|---|---|---|
| `conftest.py` 的 `clean_database` 无条件 `DETACH DELETE` 全库 | 跑一次 `pytest` 清空演示图谱 | 已改为非空库跳过；需破坏性测试要显式设 `ALLOW_DESTRUCTIVE_TESTS=true` |
| `activate()` 会降级**任何**其它 ACTIVE run，包括线上的 | 测试跑完线上失去 ACTIVE run | 已加 `isolated_active_run` fixture 摘挂现网 run |
| 测试实体用真实药名，`canonical_id` 与线上撞车 | `upsert` 改写线上 `run_id`，cleanup 时 `DETACH DELETE` 误删真实实体（人参、藜芦、脾经、呕吐） | 测试实体名一律加 `ITEST药` 前缀；cleanup 改为 run_id 与名称前缀双条件 |

**教训**：只要测试与生产共库，隔离就必须覆盖每一个全局命名空间——节点、
全局唯一状态、以及由纯函数派生的身份（`canonical_id` 是 `(类型, 规范名)` 的纯函数，
名字一样身份就一样）。

**根治办法**是给测试单独起一个 Neo4j 实例，属 Owner E 的 CI 工作，尚未做。

## 3. 引用评测数字必须连同口径

抽取质量的数字是 **Recall@field 85.2%**，但它有严格的适用范围：

- 参照集是「教材结构化字段」（`【药性】`/`【功效】`/`【用法用量】`），
  **不是**双人标注仲裁的金标准；
- 只覆盖 **性味/归经/功效**，**主治、配伍、禁忌没有任何参照**；
- Precision 标注 ↓ 表示**下界**——图谱合理包含字段之外的正确事实
  （【应用】段落、跨章节引用），它们不在参照集里但并不算错。

✅ 可以说：「在教材结构化字段上，字段召回率 85.2%」
❌ 不能说：「抽取准确率 85%」

同理，`final_score` 是排序与决策支持值，**不是事实正确概率**。

## 4. 数据包含教材 OCR 全文

`dist/zhongyaoxue-kg-bundle.zip` 里 870 个 Chunk 节点带的是教材逐字原文。

**公开仓库的 Release 附件同样是公开可下载的**（实测匿名请求返回 206）。
发布前确认分发范围符合授权；必要时把仓库转私有，或分发去掉 `Chunk.text` 的精简版。

`.gitignore` 已排除 `dist/*.zip`、`origdata/`、`.cache/`、`.env`。

---

## 5. 改 Prompt 或 Schema 必须升版本

抽取缓存键是 `内容哈希 + prompt_version + schema_version`（`config/settings.py`）。
**只改 Prompt 文字而不升版本号，缓存不会失效，改动不生效**且难以察觉。

改动后请同步升 `settings.py` 里的 `prompt_version` / `schema_version`。

---

## 6. `EMBED_CACHE_DIR` 不做 `~` 展开

`external_embedder.py` 直接 `Path(cache_dir).mkdir()`，写 `~/.cache/huggingface`
会在**仓库里创建一个名叫 `~` 的字面量目录**，模型下到那儿导致
`Unrecognized model in BAAI/bge-small-zh-v1.5`。

请填绝对路径，或**留空**让 huggingface 自行决定（推荐，`.env.example` 已改为留空）。

---

## 7. Neo4j 版本锁 5.26 LTS

2026 系列已把 `db.index.vector.queryNodes` 标记为 deprecated，而代码依赖它。
`docker-compose.yml` 固定 `neo4j:5.26-community`，不要改成浮动 tag。

全文索引必须用 `cjk` 分析器，否则中文按单字切。分析器**只能在创建时指定**，
`IF NOT EXISTS` 不会修改既有索引——`ensure_schema` 因此会先 DROP 再建。

---

## 8. `neo4j_graphrag` 仍在 9 个文件中

团队规范 §3.8 要求主链摘除，目前仍被以下文件依赖：

```
backend/api.py（四种旧检索模式）      graphragexpr/extract/rag_graph.py
graphragexpr/extract/rag_vector.py    graphragexpr/extract/create_index.py
graphragexpr/external_embedder.py     graphragexpr/custom_embedder.py
scripts/import_kg_bundle.py           scripts/rebuild_embeddings.py
tests/test_retrieval.py
```

其中检索侧属 Owner C，embedder 基类继承是共用依赖。**建图主链（v2 管线）已不依赖它。**

---

## 9. 剂量类事实要额外当心

`HAS_DOSAGE`、`CONTRAINDICATED_IN`、`INCOMPATIBLE_WITH` 在本体里标了 `high_risk`，
**无论规则分多高都强制走二次校验**。前端答案也会附「以教材原文和专业人员意见为准」。

不要为了提高召回而放宽这三个谓词的阈值。
